# Maddies NLP - FinNLP 2026 Subtask 2

This archive contains the complete API workflow used for the Maddies NLP submission to Japanese Implicit Communication Recognition (JF-ICR).

## Eligibility

- API provider: OpenRouter only
- Model: `google/gemma-4-31b-it`
- Model URL: <https://openrouter.ai/google/gemma-4-31b-it>
- Model size: 30.7B total parameters (dense), below the 70B competition limit
- Other models used at inference: none
- Fine-tuning, retrieval, external labels, and manual test edits: none

## Architecture

Each example uses two normal calls to the same Gemma model:

1. Stage 1 reads the Japanese question and response and extracts label-blind tagged evidence about the target proposition, clause modality, actor/control, negation scope, conditionality, and institutional anchors.
2. Stage 2 receives the original Japanese and the complete Stage-1 evidence. It applies the frozen five-level ordinal rubric and emits the final label first.

Stage 1 is retried once only when its outer tagged format is incomplete. Stage 2 is repaired once only when no explicit final label marker can be parsed. A Stage-2 repair does not regenerate Stage 1.

The exact prompts are in `prompts.py`. Sampling settings and pinned OpenRouter providers are in `config.json`.

## Environment

Python 3.10 or newer is recommended.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
export OPENROUTER_API_KEY="YOUR_KEY"
```

Do not place an API key in source code or in the submitted archive. The runner also recognizes a local `.env` file containing `OPENROUTER_API_KEY=...`; `.env` is intentionally excluded from the archive.

## Input

The runner accepts Parquet, CSV, or JSONL. It supports either organizer format:

```text
id, query
```

where `query` contains the `Financial Question:` and `Company Response:` fields, or a pre-parsed format:

```text
id, financial_question, company_response
```

IDs must be unique. Gold labels are never read or included in API messages.

## Exact Submitted Run

From the archive root, run:

```bash
.venv/bin/python inference.py \
  --input /path/to/JF-ICR_test_participant.parquet \
  --output submission.csv \
  --run-dir run_artifacts \
  --expected-rows 50 \
  --budget-cap 2.00
```

The workflow uses four concurrent workers. For a verifier-provided set with a different number of rows, change `--expected-rows` or omit it. This does not change prompts, routing, model settings, or label parsing.

To validate input parsing and produce a manifest without making API calls:

```bash
.venv/bin/python inference.py \
  --input /path/to/input.parquet \
  --run-dir dry_run_artifacts \
  --expected-rows 50 \
  --dry-run
```

## Outputs

- `submission.csv`: exactly `id,prediction`
- `run_artifacts/manifest.json`: model, settings, and SHA-256 hashes recorded before calls
- `run_artifacts/raw_outputs.jsonl`: Stage-1 and Stage-2 raw outputs and parsed labels
- `run_artifacts/api_log.jsonl`: per-call cache key, latency, token usage, and raw response
- `run_artifacts/summary.json`: row counts, prediction distribution, retries, repairs, and conservative budget reservation
- `cache/`: keyed OpenRouter responses for deterministic replay

The runner stops instead of guessing when a final label remains invalid after the one permitted formatting repair.

## Tests

```bash
.venv/bin/python -m unittest -v test_inference.py
```

The tests are local and make no API calls.

## Reference Artifacts

`reference_submission.csv`, `original_manifest.json`, and `original_summary.json` contain the leaderboard CSV generated by the frozen workflow, its pre-call manifest, and its summary. The submitted Gemma CSV received 0.9333 accuracy on the 15-example public leaderboard.

## Files

- `inference.py`: complete inference, validation, caching, and logging workflow
- `prompts.py`: exact frozen Stage-1, Stage-2, and formatting-repair prompts

- `requirements.txt`: runtime dependencies
- `test_inference.py`: local parser and validation tests
